## 1. ROS1과 ROS2의 통신방식의 관점에서 차이를 설명하라

ROS1은 XMLRPC와 TCPROS를 사용하며, ROS Master가 모든 노드의 이름·토픽·서비스 정보를 중앙에서 관리해 노드 간 연결을 중개한다.
ROS2는 산업 표준 미들웨어 DDS(RTPS)를 사용하여 중앙 Master 없이 각 노드가 DDS Participant로서 Dynamic Discovery를 통해 서로 자동으로 검색·연결(P2P)한다.
그 결과 ROS1은 Master 장애 시 전체 시스템이 마비되지만, ROS2는 단일 장애점이 없고 QoS 설정도 가능하다.

## 2. ROS1의 통신 미들웨어인 TCPROS와 ROS2의 통신 미들웨어인 DDS의 차이를 설명하라

TCPROS는 ROS 자체 개발한 TCP 기반 통신 라이브러리로, ROS Master의 IP·포트만 알면 시스템 전체에 접근 가능해 보안에 취약하고 QoS 설정 기능이 없다.
DDS는 OMG에서 표준화한 산업용 Publish-Subscribe 미들웨어로 RTPS 프로토콜과 IDL을 사용하며, Dynamic Discovery와 DDS-Security, QoS(신뢰성·속도 등) 설정을 지원한다.
또한 DDS는 ADLink, RTI 등 여러 벤더 중 선택 가능(RMW)하다는 점도 TCPROS와 다르다.

## 3. 실시간 시스템(Real-time System)의 정의를 조사하라

실시간 시스템은 주어진 작업을 정해진 시간(데드라인) 안에 반드시 완료하는 것을 목표로 하는 시스템으로, 결과값의 정확성뿐 아니라 응답 시간의 예측 가능성이 핵심이다.
데드라인을 넘기면 시스템 실패로 간주되는 경성(Hard) 실시간 시스템과, 지연이 성능 저하로만 이어지는 연성(Soft) 실시간 시스템으로 구분된다.
로봇 제어처럼 모터·센서 제어 타이밍이 중요한 분야에서는 주로 경성 실시간 특성이 요구된다.

## 4. GPL 라이선스와 Apache 2.0 라이선스의 차이를 설명하라

GPL은 대표적인 Copyleft 라이선스로, GPL 코드를 사용·수정한 소프트웨어를 배포할 경우 그 소스코드도 동일한 GPL로 공개해야 한다.
Apache 2.0은 permissive(허용적) 라이선스로, 저작권 및 라이선스 고지만 유지하면 소스 공개 의무 없이 수정·재배포·상업적 이용이 가능하다.
또한 Apache 2.0은 명시적인 특허 라이선스 조항을 포함해 GPL보다 특허 관련 분쟁 위험을 줄여준다.

## 5. 멀티 프로세싱(Multi-processing)을 설명하라

멀티 프로세싱은 하나의 작업을 여러 개의 프로세스로 나누어 동시에 실행함으로써 처리 성능을 높이는 방식이다.
각 프로세스는 독립된 메모리 공간을 가지므로 안정성이 높지만, 프로세스 간 통신(IPC)에는 별도의 메커니즘이 필요하다.
ROS에서는 노드를 별도 프로세스로 실행하여 멀티 프로세싱을 자연스럽게 구현한다.

## 6. 분산 컴퓨팅(Distributed Computing)을 설명하라

분산 컴퓨팅은 하나의 작업을 네트워크로 연결된 여러 대의 컴퓨터(노드)에 나누어 처리하고 그 결과를 통합하는 컴퓨팅 방식이다.
단일 컴퓨터의 한계를 넘는 확장성과 가용성을 얻을 수 있지만, 노드 간 통신 지연과 동기화, 장애 처리가 중요한 과제가 된다.
ROS는 여러 대의 로봇·컴퓨터에 노드를 분산 배치해 통신하게 함으로써 분산 컴퓨팅 구조를 지원한다.

## 7. 네트워크 통신(Network Communication)을 설명하라

네트워크 통신은 물리적으로 분리된 두 개 이상의 장치(컴퓨터, 로봇 등)가 네트워크를 통해 데이터를 주고받는 것을 의미한다.
정해진 프로토콜(TCP/IP, UDP 등)에 따라 데이터를 패킷 단위로 전송하며, 신뢰성이 필요한 경우 TCP, 속도가 중요한 경우 UDP를 사용한다.
ROS1은 TCPROS(TCP 기반), ROS2는 DDS(RTPS, TCP/UDP 모두 가능)를 통해 노드 간 네트워크 통신을 수행한다.

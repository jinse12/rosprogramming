# 실습과제

## 1. 메타운영체제, 소프트웨어 플랫폼, 프레임워크, 미들웨어에 대하여 각각 설명하라.

### 1-1. 메타운영체제 (Meta-Operating System)

- 애플리케이션과 분산 컴퓨팅 자원 사이의 **가상화 레이어**로, 분산된 컴퓨팅 자원을 활용하여 스케줄링, 로드, 감시, 에러 처리 등을 실행하는 시스템이다.
- 윈도우, 리눅스, 안드로이드 같은 **전통적인 운영체제가 아니다.** 기존 운영체제(리눅스, 윈도우, macOS 등) 위에서 동작하는 응용 프로그램이다.
- 프로세스 관리, 파일 시스템, 유저 인터페이스, 컴파일러, 스레드 모델 등은 **기존 운영체제의 기능을 그대로 사용**한다.
- 그 위에 여러 이기종 하드웨어 간의 데이터 송수신, 스케줄링, 에러 처리 등 **로봇 소프트웨어 개발에 필요한 기능을 라이브러리 형태로 추가 제공**한다.
- ROS는 이름에 Operating System이 들어가지만 실제로는 메타운영체제에 해당한다.

### 1-2. 소프트웨어 플랫폼 (Software Platform)

- 응용 프로그램을 개발하고 실행할 수 있는 **기반 환경 전체**를 말한다.
- 개발 도구, 라이브러리, 실행 환경, 배포 방식, 사용자 커뮤니티까지 포함하는 넓은 개념이다.
- 예: 안드로이드 위에서 수많은 앱이 개발·유통되는 것처럼, ROS 위에서도 다양한 로봇 응용 프로그램이 개발되고 패키지 단위로 공유된다.
- ROS는 SDK, 드라이버, 최신 알고리즘, 개발 도구를 제공하고, 사용자가 개발한 패키지가 유통되는 **생태계(ecosystem)** 를 갖춘 로봇 소프트웨어 플랫폼이다.

### 1-3. 프레임워크 (Framework)

- 특정 분야의 프로그램을 쉽게 만들 수 있도록 **구조(뼈대)와 규칙을 미리 정해 놓은 소프트웨어**이다.
- 개발자는 프레임워크가 정한 구조에 맞춰 필요한 부분만 작성하면 된다.
- 라이브러리는 개발자가 필요할 때 호출하지만, 프레임워크는 **프레임워크가 정한 흐름 안에서 개발자의 코드가 호출**된다는 차이가 있다(제어의 역전).
- ROS에서는 프로그램을 **노드** 단위로 나누고, 노드 간 통신을 토픽·서비스·액션으로 하며, **패키지** 단위로 관리하는 구조가 정해져 있다. 개발자는 이 구조에 맞춰 노드의 기능만 작성하면 된다.

### 1-4. 미들웨어 (Middleware)

- 운영체제와 응용 프로그램 사이(middle)에서 동작하며, 서로 다른 프로그램이나 컴퓨터가 **데이터를 주고받을 수 있도록 연결해 주는 소프트웨어**이다.
- 통신, 데이터 변환, 동기화 같은 복잡한 처리를 대신해 주므로, 개발자는 통신의 세부 구현을 몰라도 된다.
- ROS는 노드 간 메시지 통신을 담당하는 미들웨어 역할을 하며, ROS2에서는 실제 통신을 **DDS**가 담당한다.

### 1-5. ROS와의 관계 정리

| 용어 | 핵심 의미 | ROS에서의 모습 |
|---|---|---|
| 메타운영체제 | 기존 OS 위에서 분산 자원을 관리하는 가상화 레이어 | Linux/Windows/macOS 위에서 동작하며 로봇용 기능을 추가 제공 |
| 소프트웨어 플랫폼 | 개발·실행·유통을 위한 기반 환경 전체 | SDK, 도구, 패키지 생태계 |
| 프레임워크 | 구조와 규칙이 정해진 개발 뼈대 | 노드, 패키지, 토픽·서비스·액션 구조 |
| 미들웨어 | 프로그램 간 통신을 연결하는 중간 소프트웨어 | DDS 기반 노드 간 메시지 통신 |

ROS의 목적은 로봇 소프트웨어 개발 **플랫폼, 미들웨어, 프레임워크**를 지향하는 것이다. 이를 통해 로보틱스 연구·개발에서 코드 재사용을 극대화하고, 전 세계 개발자가 함께 작업할 수 있는 생태계를 구축하는 것이다.

## 2. DDS에 대하여 조사하고 ROS에서 DDS의 역할은 무엇인가?

### 2-1. DDS (Data Distribution Service)란?

- OMG(Object Management Group)에서 표준으로 정한 **데이터 분산 서비스 통신 미들웨어**이다.
- **발행/구독(Publish/Subscribe) 방식**으로 데이터를 주고받는다. 데이터를 보내는 쪽과 받는 쪽이 서로를 직접 알 필요가 없다.
- 국방, 항공, 교통, 산업 자동화처럼 실시간성과 신뢰성이 중요한 분야에서 사용되어 왔다.

**주요 특징**

| 특징 | 설명 |
|---|---|
| 분산형 구조 | 중앙 서버(ROS1의 roscore 같은 마스터) 없이 노드끼리 직접 통신한다. 하나가 멈춰도 전체 시스템이 멈추지 않는다 |
| 자동 탐색 (Discovery) | 같은 네트워크의 참여자들을 자동으로 찾아 연결한다 |
| QoS (Quality of Service) | 신뢰성(Reliable/Best effort), 데이터 보관 개수(History/Depth), 지속성(Durability) 등 통신 품질을 데이터별로 설정할 수 있다 |
| 표준 프로토콜 RTPS | DDS 제품끼리 통신할 수 있도록 표준 전송 프로토콜(RTPS, 주로 UDP 기반)을 사용한다 |
| 보안 | DDS-Security 표준으로 인증, 암호화, 접근 제어를 지원한다 |
| 실시간성 | 임베디드, 실시간 시스템에서도 사용할 수 있도록 설계되었다 |

**대표적인 DDS 구현체:** eProsima Fast DDS, Eclipse Cyclone DDS, RTI Connext DDS

### 2-2. ROS2에서 DDS의 역할

ROS2 구조는 다음과 같이 계층으로 나뉜다.

```
Application Layer      : User Code (ROS2 노드)
ROS2 Client Layer      : rclcpp(C++), rclpy(Python) → rcl(C 구현)
Abstract DDS Layer     : rmw (ROS Middleware Interface)
DDS Implementation     : Fast DDS / Cyclone DDS / Connext DDS
Operating System       : Linux / Windows / macOS
```

1. **노드 간 실제 통신을 담당한다.** 토픽, 서비스, 액션으로 주고받는 메시지는 모두 DDS를 통해 네트워크로 전달된다.
2. **마스터 없는 분산 통신을 가능하게 한다.** ROS1은 roscore(마스터)가 있어야 노드끼리 연결됐다. ROS2는 DDS의 자동 탐색 기능 덕분에 마스터 없이 노드들이 서로를 찾는다.
3. **QoS로 상황에 맞는 통신을 제공한다.** 예를 들어 센서 데이터는 빠른 전송(Best effort), 제어 명령은 확실한 전달(Reliable)처럼 데이터 특성에 맞게 설정할 수 있다.
4. **보안·실시간·다중 로봇 통신을 지원한다.** 불안정한 네트워크 환경, 여러 대의 로봇, 임베디드 장치에서도 사용할 수 있게 해 준다.
5. **rmw 계층을 통해 DDS를 교체할 수 있다.** rmw가 DDS 구현의 세부사항을 숨겨 주기 때문에, 사용자 코드를 바꾸지 않고 Fast DDS, Cyclone DDS 등 원하는 DDS를 선택해 사용할 수 있다.

**정리:** ROS2는 통신 기능을 직접 만들지 않고, 검증된 산업 표준인 DDS를 미들웨어로 채택했다. 그래서 DDS는 ROS2에서 **노드들을 연결하는 통신의 기반(데이터 버스)** 역할을 한다.

## 3. ROS를 응용한 제품 또는 자율주행 프로젝트 사례를 3가지 이상 조사하라. 산업계에서 실제로 얼마나 많이 사용하는지 확인해 볼 것

### 3-1. 사례

| # | 기업/기관 | 제품·프로젝트 | ROS 활용 내용 |
|---|---|---|---|
| 1 | **TIER IV / Autoware Foundation** (일본) | **Autoware** (오픈소스 자율주행 소프트웨어) | 2015년 나고야대학에서 시작된 자율주행 소프트웨어로, ROS 기반으로 만들어졌다(현재 버전은 ROS2 기반). 인지·판단·제어 기능을 모듈로 제공하며, TIER IV가 개발을 주도하고 Autoware를 탑재한 차량으로 전 세계에서 실증 실험을 진행하고 있다 |
| 2 | **NASA** | **VIPER** (달 탐사 로버) | 지구에서 로버를 운용하는 시스템에 ROS2와 Gazebo 시뮬레이터를 사용했다. 기존 코드 약 28만 줄을 재사용했고, 달 환경을 Gazebo 플러그인으로 시뮬레이션했다 |
| 3 | **OTTO Motors** (캐나다) | 공장·물류창고용 자율이동로봇(AMR) | ROS2로 로봇 군집(fleet) 관리를 구현해 수십 대에서 100대 이상으로 확장했다. 누적 운행 200만 시간 이상, 150만 km 이상 주행했다 |
| 4 | **Ghost Robotics** (미국) | Vision-60 4족 보행 로봇 | 소프트웨어의 약 90%가 ROS2 기반이며, 통신과 자율 동작 구조에 ROS2를 사용한다 |
| 5 | **Auterion** (스위스) | Skynode 드론 자동조종 장치 | ROS2의 rosbag2로 비행 데이터를 기록·분석하고, Gazebo로 연간 약 2만 2천 시간의 비행 시뮬레이션을 수행했다 |

### 3-2. 산업계 사용 현황

- 시장조사기관 ABI Research는 2019년 발표에서 2024년에 출하되는 상업용 로봇의 약 55%(91만 5천 대 이상)에 ROS 패키지가 최소 하나 이상 설치될 것으로 전망했다.
- 같은 발표에서 Microsoft, Amazon, Google, NVIDIA 같은 대기업과 로봇 기업들이 ROS를 지원하고 있다고 소개했다.
- 위 사례처럼 자율주행 자동차, 우주 탐사, 물류 로봇, 보행 로봇, 드론 등 다양한 산업 분야에서 ROS가 사실상 표준 플랫폼으로 사용되고 있다.
- 특히 ROS2는 DDS 기반의 실시간성, 보안, 다중 로봇 통신을 지원하기 때문에 연구용을 넘어 상용 제품에 적용되는 사례가 늘고 있다.
